# 「秘书」—— 可复用的"本质锚定"系统（独立主库）

> 一句话：秘书不做事，秘书保证**每一步都锚在本质上**——接入任何项目，都能快速理清它的**本质、框架、结构**，判断**状态**，找出**核心**，并用任务追踪器让后续每一步不漂移。
> **本目录是秘书的工程主库**：只做方法层演进、模板/脚本维护、全量项目登记。**不直接服务任何具体项目的执行**——接入项目时克隆一份到该项目目录，在克隆副本中执行（隔离规则见第三节）。

## 一、创始指令（为什么秘书存在，原文见 `method/00_秘书宪法.md`）

1. 世界上的事情大多浮于表面，表面的"量化修正"没有意义——真正的关键点是找到**底层逻辑的核心点**，以此为核心展开，即**找到本质**；
2. 以核心思考为起点，像架构师一样**构建框架**——永远不被表象迷惑，也不被自己的语言迷惑，只看事情的本质；
3. 生成**任务追踪器**——之后的每一步都抓住最核心的本质；执行中难免出现偏差（上下文记忆偏差、执行者判断偏差、语言包装偏差），所以每一步都要**铭记最开始、最基础的核心内容和框架**。

## 二、结构

```
秘书/                          ← 本目录（独立主库）
├── README.md                   ← 你在这
├── init.sh                     ← 接入脚本（在克隆副本内使用）
├── 自身_日志.md                 ← 秘书自身的执行记录 + 方法层偏差沉淀（只追加）
├── method/                     ← 方法层（通用引擎，所有项目共用）
│   ├── 00_秘书宪法.md             创始指令原文 + 秘书的核心命题 + 秘书自身三问（不可变）
│   ├── 01_本质勘察法.md           接入任何项目的勘察 SOP
│   ├── 02_执行协议.md             每一步的标准动作
│   ├── 03~05_模板*.md             实例三件套的生成模板
│   └── 06_接入手册.md             接入四步 + 最低产出标准
└── projects/
    └── README.md                  总登记表（每个项目由哪个克隆副本服务）
```

## 三、部署模式与隔离规则

| | 独立主库（本目录） | 克隆副本（如 `<项目目录>/秘书`） |
|---|---|---|
| 持有 | method/、init.sh、总登记表、自身_日志 | method/（冻结拷贝）、init.sh、该项目实例（projects/<名>/） |
| 职责 | 方法层演进、登记、方法层偏差沉淀 | 只服务所接入的项目：勘察、追踪、偏差记录 |
| 禁止 | 持有任何项目实例数据 | 修改方法层（改动先回主库走提案，通过后同步副本） |

**铁律：主库不碰项目数据，副本不碰方法层，两者互不污染。** 副本出现同类偏差 ≥3 次需要升级方法层时，连同证据回主库 `自身_日志.md` 提案。

## 四、快速接入一个新项目

1. 克隆副本：`cp -R 秘书 <项目目录>/秘书`（或 `cd <项目目录> && bash 秘书/init.sh <项目名>` 建测试实例）；
2. 在副本内按 `method/01_本质勘察法.md` 勘察：收集原话 → 剥壳 → 找链 → 定制三问 → 盘点诊断 → 输出四件套；
3. 之后每一步按 `method/02_执行协议.md`：开工读锚点卡 → 行为句 → 本质三问 → 追踪器记录 → 完工核对 → 偏差记日志。

## 五、权威链

```
method/00_秘书宪法.md（创始指令原文）
  → method/01~06（方法层）
  → 项目宪法/创始人原话
  → 克隆副本 projects/<项目名>/00_核心锚点.md
  → 克隆副本 projects/<项目名>/02_任务追踪器.md、03_偏差日志.md
```

冲突时：上层优先；**原文优先于一切蒸馏。**

## 六、项目登记

主库不登记具体项目（零污染）；接入登记发生在克隆副本的 `projects/README.md`（init.sh 自动追加）。主库 `projects/README.md` 仅保留模板。
